25·2 · Exigences qualité

  • EF : ce que le produit doit accomplir. ENF : comment (= contraintes de conception). Sources : RFP, SOW, CONOPS, spéc. système.
  • Modèle de qualité : caractéristiques + relations pour spécifier et évaluer (donc mesurer).
  • Interne vs externe (maintenabilité) : testabilité = nb de chemins du graphe de contrôle, sans exécution ; analysabilité = effort pour trouver la cause d'une défaillance, en exécution.
  • IEEE 1061 (1998) : cadre de mesure, exemples sans prescrire. Qualité → facteurs → sous-facteurs → mesures.
  • A = dispo / (dispo + non dispo) · 37,5/(37,5+2) = 94,9 % < 95 %. Panne max = fenêtre × (1 − cible) : 168 h × 0,5 % = 0,84 h.
  • SQuaRE = Quality Requirements and Evaluation (ISO 25000 ; relève d'ISO 9126 de 1991, peu utilisée). Divisions : 2500n gestion · 2501n modèle (25010) · 2502n mesure · 2503n exigences · 2504n évaluation. Étapes : exigences → modèle → mesures → évaluations.
  • 3 modèles : de fonctionnement (in use) · du produit · des données.
  • In use : efficacité · efficience · satisfaction · mitigation des risques · couverture contextuelle. Efficacité = atteindre le but ; efficience = avec peu de ressources.

25·3 · Sécurité des artéfacts IAG

  • 4 surfaces : A ce que le modèle écrit · B ce qu'il lit · C ce que l'outil fait · D ce que l'humain ne fait plus. La revue humaine ne corrige ni B ni D.
  • Code généré : compile ~100 %, ~44 % vulnérable (réussite 56 %, stagnation). Perry : moins sûr, mais on se croit plus en sécurité.
  • Nouveaux : 2, 3, 5, 6 (paquet halluciné, injection par le dépôt, agents sur-privilégiés, outillage IA/MCP). Amplifiés : 1, 4, 7, 8, 9, 10. Nº 9 écart de vérification = multiplicateur. Ne pas négliger nº 7 (contrôle d'accès, 1er OWASP).
  • Injection : Unicode invisible dans CLAUDE.md, .cursorrules → refuser les non-imprimables en IC. Agents : contrôle hors de l'agent (bac à sable, moindre privilège). AIBOM : agents, outils, serveurs MCP.
  • Un contrôle qui repose sur la vigilance = une recommandation. Chaque contrôle doit être mécanique.
  • Slopsquatting : 19,7 % des paquets suggérés n'existent pas ; faux nom reproductible → l'attaquant le publie ; hook PostInstall avant le 1er import.
  • Contre-mesures : miroir + quarantaine > verrouillage > SCA en porte d'IC > installation sans exécution > règle de revue.
  • 6 politiques de quarantaine : âge (7-30 j) · vulnérabilités · réputation · licence · comportement · provenance. Le halluciné échoue à âge, réputation, comportement. Limite : --index-url contourne → bloquer au pare-feu.
  • ==2.32.3 = reproductibilité (qualité) ; --hash = intégrité (sécurité). pip install --require-hashes · runner : npm ci (+ --ignore-scripts). Le verrou fige aussi le mal.
  • SCA : A CVE (inutile contre un nom halluciné) · B paquets malveillants (après installation). Meilleurs : deptry, quarantaine, vérif. d'existence sur le SBOM.
  • Python only-binary = :all: · npm ignore-scripts · Maven : JAR inerte, plugins exécutés. Charge → __init__.py : réduction, pas prévention.

  • ★ Combien de normes en GL ? entre 120 et 300 (SC7 : 5 → >160 en 2016).

  • ISO + IEC → JTC 1 / SC 7 (WG 24 : ISO 29110 TPE ; WG 20 : SWEBOK). SC 27 sécurité.
  • ★ SWEBOK v4 : corpus de ce que l'ingénieur logiciel doit maîtriser, 17 domaines (nouveaux : architecture, opérations, sécurité). Disciplines connexes (génie info, informatique, gestion de projet, génie des systèmes…) : il ne fait que délimiter la frontière et renvoie à leurs corpus.

26·5 · Gestion du risque ★

  • Risque = probabilité × conséquence (ISO 16085) ; positif ou négatif (PMBoK). Très élevé = opportunité → comité de direction, jamais seul.
  • Reprises = 40-50 % du coût de développement.
  • ★ Étapes (PMI) : identification · analyse qualitative · analyse quantitative et réponse · surveillance. Boehm : évaluation (identifier, analyser, prioriser) + contrôle (planifier, résoudre, surveiller) + leçons.
  • ★ 4 types : techniques · de gestion · contractuels/juridiques · liés au personnel.
  • Énoncé : condition + conséquence. Identifier : entrevues, FFOM, Ishikawa, listes.
  • Probabilité 6.10 : 1 peu probable · 2 faible · 3 probable · 4 très probable · 5 presque sûr. Conséquence 6.8 : 5 = jalons impossibles / budget +>15 %.

16·1 · Plan qualité (IEEE 730) ★

  • Plan qualité = revue du plan de projet par l'AQL ; synthèse du cours.
  • ★ Maison de l'AQL : base = déontologie, support de la direction, groupe d'AQL · fondations = référentiels (normes, modèles, catégories d'erreurs, terminologie) · infrastructure (GC, revues, audits, V&V, tests, politiques, procédures, mesures) · culture (coût de la qualité, déontologie, modèle et exigences qualité, fournisseurs, contrats, risque) · poutre = plan d'AQL · piliers = processus clairs, formation constante, amélioration continue · toit = livraison de qualité, employés heureux.
  • ★ But : preuves d'une confiance justifiée que le logiciel est conforme ; exigences minimales d'AQL. 1979 → 2014 (processus, harmonisée 12207).
  • Clauses : 1 aperçu · 2-3 réf., définitions · 4 concepts (4.1 direction … 4.8 SMQ) · 5 processus (5.3 mise en œuvre, 5.4 produit, 5.5 processus) · annexes A-J (C guide du plan, F agile, G 29110).
  • ★ Plan type : 1 but · 2 définitions · 3 références · 4 vue d'ensemble (organisation/indépendance, risque, outils, normes, effort) · 5 activités (produit, processus) · 6 considérations (contrat, mesure, dérogations, répétition, risques, communication, non-conformité) · 7 enregistrements. Sujets normatifs, noms/ordre informatifs ; section non applicable = emplacement + justification.
  • 16 activités : 5.3 (6) dont 5.3.6 indépendance et objectivité · 5.4 produit (5) · 5.5 processus (5) dont 5.5.4 sous-traitants, 5.5.6 compétences.
  • Direction : connaît l'AQL · fournit des ressources · reçoit l'info et agit. L'AQL d'un artéfact ≠ son auteur.
  • IDEAL : Démarrage · Diagnostic · Instauration · Action · Apprentissage.
  • IEEE 1012 : intégrité 1-4 (4 = le plus élevé). IV&V : technique · managériale · financière.
  • Note doc. : gabarit sinon 0 ; O=1, L=0,5, S=0 × poids (contenu .2/.2/.1/.1, structure .1/.1, gestion .1/.1). <60 refusé · <75 à améliorer · >85 accepté. Diapo : 65 → vrai 55.
